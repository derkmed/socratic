Architectural State

What the code actually does today, drawn from the running source rather than from the plan. Its sibling planned_architecture.html is the design as it was drawn before the prototype existed; this is where it landed.

Figure 1

The whole system

Two containers, one browser, one offline job. Solid arrows are paths that run today; dashed ones are decided but not yet built. The portability seam is a process boundary now rather than a convention — the domain runs as its own service, so an Open WebUI import below it would not resolve.

What the figure is saying

  • Two network paths to the service, two credentials. The Pipe reaches it by the compose DNS name with the shared SOCRATIC_SERVICE_TOKEN; the iframe reaches it from the learner’s browser at SOCRATIC_PUBLIC_URL with an HMAC capability token scoped to one session — because a sandboxed srcdoc frame has an opaque origin and cannot authenticate by any ambient means. ServiceDependencies keeps the two as separate fields so no handler can accept either.
  • The overlay is emitted, not returned. The Pipe awaits __event_emitter__ with an embeds event (ADR-0017). A Pipe that returns it renders nothing at all, silently.
  • Model calls only where the arrows show them. Authoring always — skeleton then pedagogy. Grading only in Advanced: Novice feedback is wholly pre-authored, so a Novice answer costs zero model calls.
  • Mode is branched on in exactly one place. Everything that varies by mode is bundled into a ModePolicy behind ModeRegistry; an if mode == anywhere else is a bug.

Dashed means decided, not built. adapters/ holds only anthropic_client.py today; the on-disk record writer of ADR-0018 and the ProfileBuilder wiring are not in the running service, and LearnerProfileRepository is not reachable from it at all. Storage is in-memory, so a restart loses every in-flight quiz.
