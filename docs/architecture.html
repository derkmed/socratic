System design · eight decisions, six ADRs

Socratic Quiz Architecture

How a learner’s question becomes a quiz, how an answer gets graded, and where the money goes. Every arrow here is the consequence of a recorded decision.

Figure 1

The portability seam

Open WebUI donates authentication, accounts and packaging. It earns that keep only if it stays replaceable, so the rule runs one way: the adapter knows about Open WebUI, and nothing below the seam does. The answer key lives below the seam and is never serialized into the page.

Figure 2

Two grading paths, and the hop between them

A Novice bank has exactly two options, so the wrong answer is knowable when the quiz is written. Its reinforcement and all three hint rungs are authored up front, which takes the model off the critical path entirely. Advanced mode is free recall, so it has to stay on it.

Figure 3

Prompt layout and the two breakpoints

Anthropic caches are isolated per workspace, not per user. That makes segment order the highest-leverage decision in the system: put learner-specific text above the first breakpoint and a million learners each pay a cold write on identical instructions.

Figure 4

The learning loop, and what closes it

The attempt record does triple duty: it is the tutor’s memory during a quiz, the audit trail afterwards, and the input the profile job reads. The rating never enters the conversation — it is a human signal about the quiz, kept beside it.

What the diagrams assume

One arrow in Figure 1 is not yet verified: whether a rich-UI iframe may fetch our API under Open WebUI’s content security policy. If it cannot, the answer event arrives via __event_call__ instead — a clunkier modal, but the same topology. Nothing else in these figures changes.

Decisions behind each figure: the seam is ADR-0002; the two grading paths and the parallel tutor call are ADR-0003; the segment layout is ADR-0001 and ADR-0006; the sealed attempt and separate rating are ADR-0005; the schema and its override branch are ADR-0004.
